# README visual specification

What the project's landing page must be, and what a machine checks about
it. Every rule here is enforced by `pnpm docs:check` unless it is marked
**human**; the tool is `tools/docs/check.ts`.

## Why this document exists

The README was accurate prose attached to three broken images. All three
pointed at Playwright baselines under
`tests/e2e/visual.spec.ts-snapshots/…-chromium-darwin.png`, which a project
rename had moved to `…-city-darwin.png` — so the landing page of a public
repository showed three broken images, and nothing in a repository with
957 unit tests looked at a single image path.

That is the shape of every rule below: something was wrong, in public, and
no check could see it.

| Drift found | Rule now enforced |
| --- | --- |
| Three README images pointed at renamed files | Every image reference must resolve on disk |
| Alt text described a state the image did not show | Alt text required, minimum length, images inspected by a human |
| README said the branch was "not deployed" after it was | Banned-phrase scan over gated documents |
| Release summary described v1.0.0 and 5 artifacts when there were 16 | Summary is generated, never hand-written |
| CHANGELOG said 2.0.0 while package metadata said 1.1.0 | One canonical product version, checked four ways |
| Metrics hand-copied from an older run | Numbers live in generated blocks fed by evidence envelopes |

## Acceptance list

### A. Structure

1. `README.md` contains these `##` sections, in this order:
   **Why it exists · How the pipeline becomes a city · Learning modes ·
   Scientific honesty · Evidence · Try it · Docs · Limitations and AI
   disclosure**.
2. The page opens with the title, a one-sentence value proposition, compact
   badges, and links to the live app, the demo, the guided tour and the
   docs, above one hero image.
3. A four-step visual story runs author → layout and routing → compiled
   execution → measurement and comparison, with a Mermaid diagram of the
   pipeline.
4. Long WISER prose lives in `docs/WISER_SUBMISSION.md`, not in the README.

### B. Images

5. The README shows **6 to 8** images. The full set lives in
   `docs/GALLERY.md`.
6. Required coverage: Missions, Explore, Accessible 2D, day, golden hour,
   night, and a phone.
7. Every image is captured by `pnpm docs:capture` from the **production
   build** with the deterministic-frame contract engaged — frozen
   `animTime`, transient messages suppressed, exactly one frame drawn.
   Reruns on the same tree produce the same bytes.
8. Desktop images are 1280x720 (16:9); the phone image is the device's own
   ratio. Files live in `docs/assets/readme/`.
9. Every image reference resolves on disk. No image exceeds **700 KiB**;
   `docs/assets/readme/` totals at most **3.5 MiB**.
10. Every image carries alt text of at least eight characters describing
    what is actually in the frame.
11. **Human:** every final image is looked at before it ships, and its alt
    text is checked against what the picture shows. Two images failed this
    on the first pass — a hero whose caption promised a replay dock that
    was not there, and a mission caption describing gates on an empty grid.

### C. Claims

12. Banned in gated documents unless the sentence denies them:
    *photorealistic*, *mistakable for a real city/place*, *not deployed*,
    *serves `main`, not this branch*, *not uploaded anywhere*, and any
    claim of measured learning gain.
13. The city is described as **a believable stylized city**.
14. Vehicles and people carry classical jobs, instructions or measured
    bits — **never** quantum states. Enforced separately over product
    strings by `packages/ui/test/transport-misconception.test.ts`.
15. Provenance and certainty labels keep their meaning wherever quoted.

### D. Numbers

16. Every measured figure in `README.md`, `docs/WISER_SUBMISSION.md` and
    `release-evidence/summary.md` sits inside a generated block:

    ```
    <!-- docs:sync start:evidence-table -->
    …written by pnpm docs:sync…
    <!-- docs:sync end:evidence-table -->
    ```

17. `pnpm docs:sync` writes those blocks from evidence envelopes;
    `pnpm docs:check` re-renders and fails if what is committed differs.
    Hand-editing a number inside a block cannot survive.
18. Test counts are read from the suites themselves on every check, not
    from a stored figure — the README has been wrong about them twice.
19. `release-evidence/summary.md` is generated in full.
20. `release-evidence/goal-check.txt` is regenerated by running the gate,
    never edited.

### E. Versions

21. One canonical product version, equal across `package.json`,
    `apps/web/package.json`, the PWA manifest in `apps/web/vite.config.ts`,
    and the newest `## [x.y.z]` heading in `CHANGELOG.md`.
22. Three other version identifiers are **deliberately independent**, and
    changing them to match the product version would be a mistake:

    | Identifier | Means | Why it is separate |
    | --- | --- | --- |
    | `TRACE_SCHEMA_VERSION` | The trace file format | It is inside `semanticHash`; moving it changes every committed sample hash |
    | `SIMULATOR_VERSION` → `generatorVersion` | The producer recorded in a trace | It is inside `artifactHash`; moving it invalidates committed traces and visual baselines |
    | Workspace package versions | Unpublished internal libraries | They are not the product |

    `docs:check` asserts rule 21 and says nothing about these, on purpose.

### F. Links and assets

23. Every relative link in `README.md`, `docs/GALLERY.md` and
    `docs/WISER_SUBMISSION.md` resolves.
24. **Human:** external links are opened once, signed out, before release.
25. The demo is described by where it actually is — the MP4 and SRT in this
    repository — with its checksum from the manifest. A video-platform URL
    is added only once one exists.

## Out of scope

Prose outside the generated markers stays hand-written. The point is not to
generate the documentation; it is to stop the claims drifting away from the
measurements while the writing stays human.
